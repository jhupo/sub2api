# 缓存用量调整

入口：账号管理 → 更多操作 → 缓存用量调整。

- 默认关闭，默认比例为 10%，支持 0–100 的整数百分比。
- 仅对勾选的上游账号生效；可以加入账号列表中已选中的账号。
- 转换量为 `floor(缓存读取 token × 比例 / 100)`，小数部分舍去。
- 缓存为 0、比例为 0、总开关关闭或账号未选中时，不转换用量。
- 仅调整响应中的用量口径，上游实际的缓存行为不变。客户端 usage、使用日志和本地计费使用调整后的数值。
- 输出 token、缓存写入 token 和总 token 不变。

例如，普通输入 1,000、缓存读取 8,000，比例 10%，调整后普通输入为 1,800、缓存读取为 7,200。

## 协议差异

Anthropic 的 `input_tokens` 不包含缓存读取，因此转换时增加 `input_tokens`，减少 `cache_read_input_tokens`。

OpenAI 的 `input_tokens` / `prompt_tokens` 和 Gemini 的 `promptTokenCount` 已包含缓存读取，因此这些总输入字段保持不变，只减少缓存子项。现有计费代码会从总输入中减去缓存，得到增加后的普通输入量。

OpenAI 返回 `usage.attribution` 时，同步调整其中的缓存读取明细；完整明细的整数舍入与汇总值对齐。`cache_write_tokens`、`cache_creation_input_tokens` 以及其他缓存创建字段保持不变。

覆盖 JSON 普通响应、SSE、OpenAI Responses WebSocket，以及 Bedrock 解码后的流式事件。未知字段和错误响应保留原样。超出已有上游响应读取限制的内容保留原样，继续交给原有的大小限制逻辑处理。

## 实现位置

- `backend/internal/pkg/usageadjustment/`：协议字段转换和响应体读取器。
- `backend/internal/repository/http_upstream.go`：响应解压之后、业务解析之前执行 HTTP 转换。
- `backend/internal/service/openai_ws_*`、`bedrock_stream.go`：二进制流和 WebSocket 在解码后、用量提取之前转换。
- `backend/internal/service/setting_cache_read_adjustment.go`：配置校验、账号匹配和缓存。
- `frontend/src/components/admin/CacheReadAdjustmentModal.vue`：管理弹窗。

配置复用现有 `settings` 表的 `cache_read_adjustment` 键。每日统计增加迁移 `244_cache_read_adjustment_usage.sql`，在 `usage_logs` 中保存每笔请求的调整快照；正常启动时自动执行迁移。保存后当前节点立即更新；其他节点最长约 5 秒刷新。已开始的响应继续使用开始处理时的比例，新的响应使用新配置。

## 每日增收

此项从 `v0.2.40` 开始提供，需部署包含迁移 244 的构建才会开始记录。

在同一弹窗切换到“每日增收”，可按日期范围（最多 93 天）、账号 ID 查询。分日采用浏览器时区。

- 原始缓存量、实际转出的 token、当时比例随用量日志持久化；以后修改比例不会改写历史。
- 使用请求当时的计费模型、价格规则和倍率，分别计算调整前后的收费。差额为“缓存调整增收”，不等于扣除上游成本、退款、支付手续费后的净利润。
- 钱包余额多扣金额与套餐额度多消耗金额单独统计，套餐消耗不作为现金收入。
- 支持 100% 转换与零倍率；缓存为 0 或没有实际转换时不产生调整记录。写入沿用请求日志的幂等约束，不重复计数。
- 无原始快照的历史数据不倒推。无法重建原始多模态缓存定价的请求保留转出量、标为未计价，不把估算混入增收。
- 明确显示已保存的开关状态；点击总开关、添加和移除账号立即保存，比例单独保存。添加账号不会自动打开总开关。

统计接口：`GET /api/v1/admin/usage/cache-read-adjustment/daily?start_date=2026-10-01&end_date=2026-10-30&timezone=Asia/Shanghai&account_id=29`。

## 管理接口

`GET /api/v1/admin/settings/cache-read-adjustment`

`PUT /api/v1/admin/settings/cache-read-adjustment`

```json
{
  "enabled": true,
  "percent": 10,
  "account_ids": [7, 8]
}
```

接口沿用现有管理端认证。比例越界、非整数或非正数账号 ID 会返回 400。

### 即时设置与账号增删

账号管理中的弹窗分为“已加入账号”和“添加账号”。总开关点击后立即保存；搜索结果点击“添加”后立即加入，已加入列表支持单个移除、全选本页和跨页勾选后批量移除。比例在输入框旁单独保存。关闭弹窗不撤销已经完成的操作。添加、移除和开关操作只修改各自字段，不覆盖外部工具刚加入的其他账号。

以下接口均支持管理员 API Key：请求头 `x-api-key: <管理员 API Key>`。普通用户的模型 API Key 没有管理权限。

| 方法 | 路径（前缀 `/api/v1/admin/settings/cache-read-adjustment`） | 请求 / 用途 |
| --- | --- | --- |
| GET | 空 | 读取开关、比例、全部账号 ID |
| PATCH | 空 | 部分修改，如 `{"enabled":true}`、`{"percent":10}`、`{"add_account_ids":[29],"remove_account_ids":[30]}` |
| GET | `/accounts?page=1&page_size=25` | 分页读取已加入账号的 ID、名称、平台，不返回凭证 |
| POST | `/accounts` | `{"account_ids":[29,31]}`，增量加入 |
| DELETE | `/accounts` | `{"account_ids":[29,31]}`，增量移除 |

增删单次最多 1000 个 ID。重复添加、移除已不在列表的账号均可安全重试。添加时校验账号存在，任一账号不存在则整次操作失败；已删除的账号仍可从调整列表移除。数据库事务锁保护增量更新，多个推送任务同时添加不会互相覆盖。其他服务实例最多在现有 5 秒配置缓存到期后生效。

`qq-sub2api-manager` 推送成功后，取创建账号接口响应的 `data.id`，再调用添加接口即可。例如，环境变量 `SUB2API_URL`、`SUB2API_ADMIN_KEY` 和 `ACCOUNT_ID` 分别为站点、管理员密钥和已推送账号 ID：

```bash
curl --fail-with-body -X POST "$SUB2API_URL/api/v1/admin/settings/cache-read-adjustment/accounts" \
  -H "x-api-key: $SUB2API_ADMIN_KEY" \
  -H 'Content-Type: application/json' \
  --data "{\"account_ids\":[$ACCOUNT_ID]}"
```

移除时将 `POST` 改为 `DELETE`，请求体相同。加入账号不会自动打开总开关或改变比例；需要开启时，单独 `PATCH` `{"enabled":true}`。此处提供对接接口，未修改 `qq-sub2api-manager` 项目。

## 本地完整服务验证

## 发布

当前版本：`v0.2.40`，使用正式版本号以兼容现有更新检查与升级脚本。`v0.2.39` 首次提供缓存调整，`v0.2.40` 增加每日增收、即时保存的账号列表及管理员 API Key 增删接口，并修复缺少响应头或使用 `identity` 编码时的兼容问题。

推送带注释的 tag 会触发现有 Release 工作流，生成 Linux amd64/arm64 安装包和多架构 Docker 镜像。本次发布使用完整发布流程；从 `0.2.38`、`0.2.39` 可通过管理后台检测并升级到 `0.2.40`。首次使用功能默认关闭，已有缓存调整配置会保留。启动时自动执行迁移 244，已有用量日志不倒推增收；升级前按现有部署流程备份数据库。

```bash
docker pull ghcr.io/jhupo/sub2api:0.2.40
```

Docker Compose 部署时将 `.env` 中的 `SUB2API_VERSION` 设置为 `0.2.40` 后重新拉取并启动。二进制部署使用 Release 中匹配服务器架构的 `sub2api_0.2.40_linux_amd64.tar.gz` 或 `sub2api_0.2.40_linux_arm64.tar.gz`，并用 `checksums.txt` 校验。

预发布 tag 强制使用完整发布流程，只推送对应版本的镜像标签，不覆盖 `latest`、主版本或次版本标签，也不向默认分支同步 VERSION。现有自动升级仅支持正式版本，故 `v0.2.38-cache.1` 不作为本次升级版本使用。
